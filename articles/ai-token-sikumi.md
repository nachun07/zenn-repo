## はじめに

ChatGPTやClaudeなどのAIを使っていると、必ず目にする「トークン」という言葉があります。

APIの料金表示を見ても「入力トークン数」「出力トークン数」という項目があり、料金を計算する際の基準になっています。つまり、**AIを使うには、トークンが何かを理解することが不可欠**なのです。

しかし、「トークンって何？」と聞かれると、答えに困る人も多いのではないでしょうか。単語？文字数？それとも別の何か？

本記事では、AIがテキストを処理する仕組みと、トークンが果たす役割について、実際の例を交えながら説明します。記事の通りに読み進めれば、次のことが理解できるようになります：

- トークンが正体は何なのか
- なぜAPIの料金がトークン数で決まるのか
- 日本語と英語でトークン数が異なる理由
- トークン効率を高めてコストを削減する方法
- AIが実際にどのように文章を「読んでいる」のか

## トークンとは何か

### トークンの基本定義

結論から言うと、**トークンはテキストを処理する最小単位**です。

よく「単語」と勘違いされますが、実はトークンはより細かい場合もあれば、粗い場合もあります。AIモデルは数値しか理解できません。テキストを処理する前に、テキストを数値に変換する必要があります。その過程で、テキストを意味のある最小単位に分割するのが、**トークン化**の役割なのです。

### 具体例で理解する

「こんにちは」という日本語の文字列を分割する場合、異なる方法があります：

- **文字単位**：「こ」「ん」「に」「ち」「は」（5トークン）
- **単語単位**：「こんにちは」（1トークン）
- **部分単語単位**：「こんに」「ちは」（2トークン）

実際のトークン化は、どの**トークナイザー**（トークン分割器）を使うかによって大きく異なります。

英語の例も見てみましょう：

```
"Hello, world!"
```

これを OpenAI の GPT のトークナイザーで分割すると：

```
Hello    → 1トークン
,        → 1トークン
world    → 1トークン
!        → 1トークン
─────────────────
合計: 4トークン
```

スペースも通常は前の単語に含まれます。

## AIが文章を読む流れ

### テキスト処理の全体像

AIが文章を読むプロセスは、以下のような流れになっています：

```
テキスト入力
    ↓
トークナイザー（分割）
    ↓
トークン列に変換
    ↓
各トークンを数値IDに変換
    ↓
数値シーケンス（ベクトル）
    ↓
モデルが処理・推論
```

モデルは、この数値シーケンスを利用して、文脈を理解し、次のトークンを予測したり、テキストを生成したりします。

## トークン化の方法：言語による違い

トークン化の方法は、**言語によって大きく異なる**ことが重要です。

### 英語の場合

英語は単語と単語の間に空白があるため、**単語単位のトークン化が比較的シンプル**です。

```
"The quick brown fox"

↓ トークナイザー

["The", "quick", "brown", "fox"]
（4トークン）
```

句読点は別のトークンに分割されます：

```
"Hello, world!"

↓

["Hello", ",", "world", "!"]
（4トークン）
```

### 日本語の場合

日本語は**空白がないため、より複雑な処理が必要**です。通常は形態素解析と呼ばれる技術を使い、文を意味のある要素に分割します。

```
「今日は天気がいい」

↓ 形態素解析

「今日」「は」「天気」「が」「いい」

↓ トークナイザー

複数のトークンに分割される
```

ただし、**日本語はトークン効率が悪い傾向**があります。同じ意味の文章でも、英語より多くのトークン数を必要とすることが多いのです。

例えば：

```
英語：「I love programming」
→ 3トークン

日本語：「私はプログラミングが好きです」
→ 5〜7トークン程度
```

同じ内容でも、日本語の方がトークン数が多くなる傾向があります。

### 中国語の場合

中国語も単語間に空白がないため、日本語と同様に複雑な処理が必要です。ただし、トークン化の最適化方法は言語によって異なるため、完全に同じアルゴリズムが全言語で同じ効率を発揮するわけではありません。

## BPE（Byte Pair Encoding）：現代的なトークナイザー

現代のLLMの多くは、**BPE（Byte Pair Encoding）**というアルゴリズムを使用しています。

### BPEの仕組み

BPEは、頻出する文字や部分文字列のペアを反復的に統合していく手法です：

**ステップ1：初期状態**

すべての文字を個別のトークンとして扱う

```
"hello" 

→ ['h', 'e', 'l', 'l', 'o']
```

**ステップ2：最も頻出するペアを統合**

例えば「l」と「l」が最も頻出なら、「ll」を新しいトークンにする

```
"hello" 

→ ['h', 'e', 'll', 'o']
```

**ステップ3：次に頻出するペアを統合**

繰り返す

```
"hello" 

→ ['he', 'll', 'o']
```

**ステップ4：語彙サイズに達するまで繰り返す**

この過程を何千回も繰り返すことで、50,000〜100,000個のトークンからなる「語彙」が構築されます。

### BPEの利点

- **言語に依存しない**：BPEは基本的にどの言語にも適用できます
- **未知の単語にも対応**：学習データにない単語も、既知のトークンの組み合わせで表現できます
- **計算効率が良い**：単語ベースよりも少ないメモリで大規模な語彙を管理できます

## トークン数が重要な理由

### 理由1：API料金がトークン数に基づく

OpenAI、Anthropic（Claude）、Google Cloud など、ほぼすべてのLLMプロバイダーは、**トークン数に基づいて料金を請求**します。

**Claude 3.5 Sonnet の料金例（2026年時点）**

```
入力：  100万トークンあたり $3
出力：  100万トークンあたり $15
```

つまり、**トークン数が少ないほど、API使用料も少なくなります**。

**GPT-4o の料金例**

```
入力：  100万トークンあたり $2.50
出力：  100万トークンあたり $10
```

同じ処理を行う場合、トークン効率が良い書き方を心がけるだけで、コストを削減できるのです。

### 理由2：コンテキスト長の制限

すべてのモデルには、**最大コンテキスト長**があります。これは一度に処理できるトークン数の上限です。この制限を超えると、古い情報が失われてしまいます。

**モデルのコンテキスト長の例**

```
Claude 3.5 Sonnet：    200,000トークン
GPT-4 Turbo：         128,000トークン
GPT-4o：              128,000トークン
Gemini 2.0：          100,000トークン
Ollama (Llama3)：      8,000トークン
```

長い文書を処理する場合、この制限を超えないよう注意が必要です。例えば、Claude の 200,000トークンは、だいたい **A4用紙60〜100枚分** に相当します。

### 理由3：レスポンス時間に影響

一般的に、**トークン数が多いほど、処理時間も長くなります**。短いテキストの方が、素早くレスポンスを得られます。

実際に試してみると：

```
短いテキスト（100トークン）    → 応答時間：1〜2秒
中程度のテキスト（1,000トークン） → 応答時間：3〜5秒
長いテキスト（5,000トークン）   → 応答時間：10〜15秒
```

## 実践的なトークン数の計算

では、実際にどの程度のテキストが何トークンになるのでしょうか。

### 英語の目安

英語では、おおよそ以下の関係が成り立ちます：

```
1トークン ≈ 4文字
1トークン ≈ 0.75単語
```

つまり、**1,000語の英語テキストは、約1,300トークン**になります。

### 日本語の目安

日本語は効率が悪いため：

```
1トークン ≈ 2〜3文字
英語より多くのトークンを消費する傾向
```

例えば、**1,000字の日本語テキストは、400〜600トークン程度** になる可能性があります。

### 実際のトークン数を確認する方法

OpenAI や Anthropic は、**トークンカウント機能**を提供しています。

**JavaScript の例（OpenAI公式ライブラリ）**

```javascript
import { encoding_for_model } from "js-tiktoken";

const enc = encoding_for_model("gpt-3.5-turbo");
const tokens = enc.encode("Hello, world!");
console.log(tokens.length); // 4
```

**Python の例**

```python
import tiktoken

enc = tiktoken.encoding_for_model("gpt-3.5-turbo")
tokens = enc.encode("Hello, world!")
print(len(tokens))  # 4
```

**Anthropic（Claude）の場合**

```python
from anthropic import Anthropic

client = Anthropic()
message = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "こんにちは"}
    ]
)
# レスポンスのメタデータに usage が含まれる
print(message.usage.input_tokens)   # 入力トークン数
print(message.usage.output_tokens)  # 出力トークン数
```

## トークン効率を高めるコツ

APIコストを削減するには、トークン効率を高める工夫が重要です。

### ❌ 悪い例 → ✅ 良い例

**不要な文字を削除**

```
❌ 「こんにちは、これはテストです。本当に必要な情報はこれです。」
（無駄な説明が多い）

✅ 「本当に必要な情報はこれです。」
（シンプルで直接的）
```

トークン削減効果：約50%

**マークダウンの過度な使用を避ける**

```
❌ # タイトル
## サブタイトル
**太字**
- リスト項目

✅ タイトル
サブタイトル（必要な場合のみマークダウン使用）
```

トークン削減効果：約20%

**プロンプトを簡潔に**

```
❌ 「以下の長い文脈を与えるので、その中から具体的な情報を
抽出して、詳細に説明してください。」

✅ 「以下から情報を抽出してください：」
```

トークン削減効果：約30%

**システムプロンプトを最適化**

```
❌ 「あなたは経験豊富なプログラマーです。JavaScriptについて
深い知識を持ち、様々なフレームワークに精通しています。
ユーザーの質問に対して、詳細で正確な回答を提供してください。」

✅ 「JavaScriptエキスパートとして回答してください。」
```

トークン削減効果：約60%

これらの工夫を組み合わせることで、**同じ品質を保ったまま30〜40%のコスト削減**が可能になります。

## トークンに関するよくある質問

### Q1：絵文字はトークンになりますか？

**A:** はい。絵文字も特殊なトークンとして扱われます。ただし、通常のテキスト文字より多くのバイトが必要なため、効率が悪い傾向があります。

例えば、「🚀」は2〜3トークンを消費する場合があります。

### Q2：改行やスペースはトークンに含まれますか？

**A:** はい。改行やスペースも通常はトークンに含まれます。ただしトークナイザーの実装によって異なります。

```
"Hello\nworld"

→ ["Hello", "Ċ\n", "world"]
```

### Q3：同じテキストでも、異なるモデルでトークン数が異なるのはなぜ？

**A:** 各モデルが異なるトークナイザーを使用しているためです。

```
GPT-4用トークナイザー    → 100トークン
Claude用トークナイザー  → 95トークン
Gemini用トークナイザー  → 110トークン
```

同じテキストでも、モデルによってトークン数が異なるので注意が必要です。

### Q4：日本語を英語に翻訳するとトークン数は変わりますか？

**A:** はい。一般的に、同じ意味の文でも、英語の方がトークン効率が良いため、トークン数が少なくなります。

```
日本語：「今日は天気がいいですね」
→ 8〜10トークン

英語：「The weather is nice today.」
→ 6〜7トークン
```

## トークンを理解するメリット

トークンについて理解することで、以下のメリットがあります：

- **APIコストを最適化**できる
- **コンテキスト長の制限**を適切に扱える
- **AIの推論プロセス**をより深く理解できる
- **効率的なプロンプト設計**ができるようになる
- **複数のモデルを比較**する際の基準が得られる

## まとめ

トークンは、AIがテキストを処理するための基本単位です。単なる「単語」ではなく、より細かい部分単語単位で分割されることもあります。

トークン化によって、テキストが数値シーケンスに変換され、モデルが処理可能になります。このプロセスを理解することで、以下が実現できます：

- **APIコストを削減**できる（同じ出力で20〜40%削減可能）
- **コンテキスト長の制限**を最適に使える
- **モデルの推論方式**がわかるようになる
- **プロンプトエンジニアリング**のスキルが上がる

言語モデルが「文章を読む」というのは、実は統計的なパターン認識であり、トークンを通じた予測的なプロセスです。この仕組みを理解することが、AIをより効果的に活用するための第一歩となるのです。
